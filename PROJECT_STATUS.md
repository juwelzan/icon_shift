## Key decisions

| Decision | Rationale |
| --- | --- |
| Single plugin package with an internal platform interface | All implementations first-party; federation adds packages without benefit. |
| Build-time tooling as a separate pure-Dart package | Keeps `image`/`yaml` out of apps; usable without Flutter. |
| YAML as the build-time source of truth, Dart config generated | The CLI must run before the app compiles and without Flutter. |
| Build profiles applied to project files (with backups) instead of generated flavors/schemes | Simple, reversible; flavors are invasive. |
| Property table duplicated (typed in plugin, plain in CLI) with a sync test | No cross-dependency; drift is caught by a test. |
| Results, not exceptions, for OS limitations; `@useResult` | Partial support is normal across platforms. |
| Variant id == Android alias meta-data == iOS icon set name | No mapping tables. |
| Android: `<data android:scheme="icon-shift-tooling"/>` on MainActivity's LAUNCHER filter | `flutter run` needs a LAUNCHER `<activity>`; the `<data>` keeps it out of launchers. |
| Runtime changes to user-owned Linux `.desktop` / Windows shortcuts deferred | Feasible but unverifiable here; opt-in design recorded in the roadmap. |
| Android package name still `com.example.icon_shift` | The publisher must choose their namespace. |
